BAGIAN II: DATABASE SCHEMA

TABEL UTAMA:
- accounts: user dengan role (user/admin/moderator), banned status, profile.
- posts: postingan (pengumuman/kegiatan/prestasi) dengan event_date, achievement_level.
- post_media: foto & video per postingan (max 10 foto, 3 video).
- comments: komentar dengan nested (max 1 level), approval, pinned.
- featured_programs: program unggulan di home & landing.
- cms_entries: konten portal dinamis (hero, section, label).
- site_settings: toggle & string settings (registration_enabled, masa_bakti, dll).
- finance_months: periode laporan keuangan.
- finance_transactions: transaksi masuk/keluar.
- page_view_logs: traffic analytics.
- surat_masuk, surat_keluar: arsip surat internal.
- ambalan_applications: pendaftaran calon pengurus.

MIGRATION FILES (di `/migrations/`):
- migration.sql: schema awal.
- migration-v2.sql s/d migration-v10.sql: incremental updates.

Detail full schema ada di file database.txt (now embedded dalam Kitab ini).
Untuk deploy: jalankan migration-v10.sql terakhir di Supabase SQL Editor.

Q: Bagaimana cara memulai dev server?
A: npm run dev (disables DEP0205 warning). Browser: http://localhost:3000

Q: Test admin features?
A: Login sebagai admin → /admin. Test users panel, role change, ban/unban.

Q: Build untuk production?
A: npm run build (ganti env vars di hosting platform dulu).

Q: Email tidak terkirim?
A: Cek RESEND_API_KEY valid & EMAIL_FROM sudah verified di Resend dashboard.

Q: Role change email tidak terkirim?
A: Ensure sendAccountRoleChangedEmail() called di setAccountRoleAction.

Q: INTERNAL_ANALYTICS_SECRET error?
A: Harus string acak, minimal 32 karakter. Restart dev server setelah ubah .env.local.

Q: Setup Supabase di environment baru?
A: Buat project baru, copy URL & keys ke .env.local, jalankan migration-v10.sql terakhir.

Q: Bagaimana struktur folder?
A: /src/app/* = routes. /src/lib/* = utilities, queries, auth. /src/components/* = UI.
   /migrations/ = SQL files. /public/ = static assets.

Q: Audit keamanan checklist?
A: Service role key server-only, no hardcoded secrets, rate limit on forms, CSP headers,
   email escape HTML, session JWT issuer/audience, banned account gate.

DATABASE: Self-Hosted PostgreSQL (bukan Supabase)
═══════════════════════════════════════════════════════════════════════════════
Project ini menggunakan self-hosted PostgreSQL dengan koneksi langsung via `pg`
(node-postgres). Tidak menggunakan Supabase client sama sekali.

Setup Database:
1. Install PostgreSQL (local atau VPS)
2. Buat database: `CREATE DATABASE da_alf;`
3. Set search_path: `CREATE SCHEMA IF NOT EXISTS app;`
4. Jalankan migration berurutan dari folder /migrations/

Environment Variables untuk Self-Hosted PostgreSQL:
  DATABASE_URL=postgresql://user:password@host:5432/da_alf?sslmode=require

  Catatan: Tidak perlu NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY,
  atau SUPABASE_SERVICE_ROLE_KEY. Semua query via src/lib/db.js (pg pool langsung).

Migration System:
- Semua migration ada di folder /migrations/
- Jalankan via: npm run migrate
- Atau manual via psql: \i migrations/migration-v15.sql (bertahap)
- Urutan: migration.sql → migration-v2.sql → ... → migration-v15.sql

Perbedaan dari Supabase:
- Tidak ada RLS (Row Level Security) — keamanan di-handle oleh aplikasi
- Tidak ada Supabase Auth — pakai JWT custom via jose
- Tidak ada Supabase Storage — upload via Cloudinary unsigned preset
- Tidak ada Supabase Realtime — semua real-time via router.refresh()

VERCEL + Self-Hosted PostgreSQL Deployment:
═══════════════════════════════════════════════════════════════════════════════
1. Di Vercel Dashboard → Settings → Environment Variables:
   - DATABASE_URL: koneksi ke PostgreSQL server (self-hosted)
   - AUTH_SECRET: random string panjang (openssl rand -hex 32)
   - RESEND_API_KEY: dari dashboard Resend
   - EMAIL_FROM: email terverifikasi di Resend
   - INTERNAL_ANALYTICS_SECRET: random string panjang
   - NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME: dari Cloudinary dashboard
   - NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET: dari Cloudinary settings
   - FOOTER_CONTACT_PHONE, FOOTER_CONTACT_EMAIL, FOOTER_WEBSITE_URL
   - NEXT_PUBLIC_SITE_URL: domain production

2. Pastikan PostgreSQL server menerima koneksi dari Vercel (whitelist IP atau
   gunakan koneksi SSL/TLS).

3. Jalankan migration via npm run migrate sebelum aplikasi berjalan.

4. Build & Deploy dari Vercel dashboard atau via git push.

CATATAN PENTING:
- Jangan commit .env atau .env.local ke git.
- AUTH_SECRET wajib diubah dari default untuk production.
- INTERNAL_ANALYTICS_SECRET wajib string random panjang.
- DATABASE_URL untuk production sebaiknya pakai connection pooler (PgBouncer).
- Rate limiter in-memory (src/lib/rate-limit.js) hanya untuk single instance;
  untuk multi-replica, upgrade ke Redis/Upstash.
